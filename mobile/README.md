# Fretboard Practice for iPhone, iPad and Android

The native app, built with [Expo](https://expo.dev) (React Native). It shares its music logic with the web site:
scales, chords, voicings, rhythms and the sound engine all come from [`../src/lib`](../src/lib), so a fix there fixes
both. The screens are native: the system tab bar, navigation bars with large titles, sheets that slide up, the
platform's own segmented controls and switches, and haptic taps.

| Tab | Status |
|---|---|
| Fretboard | Native |
| Rhythm, Training, Charts, Resources | Coming next (they open the web version for now) |

## Try it on a phone

**Android, no setup:** open the latest **Mobile apps** run in GitHub Actions, download
`fretboard-practice-android-apk`, unzip it and open the `.apk` on your phone (allow installing from your browser
or files app when asked).

**iPhone / iPad:** Apple only lets signed apps onto devices, so this needs the Apple Developer account and an EAS
build (below). With those, `eas build --profile preview --platform ios` makes an install link for registered
devices, and TestFlight works once the app is in App Store Connect.

## Code

TypeScript in strict mode, checked by `npm run typecheck` and `npm run lint` (Expo's ESLint rules, no `any`, type-only
imports, exhaustive hook dependencies); `npm run check` runs both. The shared music code in `../src/lib` stays
JavaScript for the web site; the app sees it through typed declarations in
[`src/types/shared-music.d.ts`](src/types/shared-music.d.ts), and a web test (`src/lib/sharedTypes.test.js`) fails if
a declared export disappears. Saved settings are typed too: every key, its type and default live in
[`src/lib/prefs.ts`](src/lib/prefs.ts), and a stored value of the wrong type falls back to the default.

## Develop

```bash
cd mobile
npm ci
npx expo run:android   # needs Android Studio; or
npx expo run:ios       # needs a Mac with Xcode
```

The app uses native modules (sound, SQLite storage), so it runs in a development build, not in Expo Go.
`ios/` and `android/` are generated by `expo prebuild` and are not committed; configure them through `app.json`.

## Build and publish with EAS (no Mac needed)

[EAS](https://expo.dev/eas) builds and signs both apps in the cloud and can upload them to the stores.

1. Create a free account at <https://expo.dev/signup>, then in `mobile/`: `npx eas-cli@latest login` and
   `npx eas-cli@latest init` (this adds the project id to `app.json`; commit that change).
2. **Android:** `npx eas-cli@latest build --platform android --profile production`. EAS creates and keeps the
   upload key for you. Download the `.aab` and upload it in Play Console, or run `eas submit --platform android`.
3. **iOS:** `npx eas-cli@latest build --platform ios --profile production`, sign in with your Apple Developer
   account when asked (EAS creates the certificates), then `npx eas-cli@latest submit --platform ios` to send it to
   App Store Connect / TestFlight.

Build numbers go up automatically on every production build (`eas.json`), and the version players see is
`version` in `app.json`.

App id: `io.github.joeyf116.fretboard` on both stores. It can change until the first upload, never after.
